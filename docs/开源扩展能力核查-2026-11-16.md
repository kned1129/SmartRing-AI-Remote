# 开源扩展能力核查

## 会话列表

ChatGPT Classic 和 GrokBot 当前代码没有会话列表读取器；DeviceFeatures.sessions 对非Codex直接返回unsupported。这只能证明未适配，不能证明永远读不到。后续可分别调查官方接口、本地只读存储、可访问性控件；本轮未穷尽这些方法，不承诺能读取完整列表。

Codex已有本地只读列表与回复分页，但可靠的指定历史会话激活及会话ID绑定尚未实现。三种软件的当前窗口输入操作与历史读取是分开的。

## 配置与扩展的真实边界

| 项目 | 当前状态 |
|---|---|
| 自己的Wi-Fi、主机地址、配对令牌 | Configure.cmd生成本机配置；改变固件网络参数后需重新编译 |
| AI已运行窗口识别 | adapters里的进程文件名、窗口正则、输入框正则、automation_id可配置 |
| AI的任意可执行文件路径及自动启动 | 尚未实现；processes匹配的是文件名，不是exe路径；程序须自行启动 |
| 任意新增AI及动态页面名称 | 尚未实现；固件三入口名称固定，改名称或数量需要改源码和重编译 |
| 任意软件当前输入框听写 | 有全局模式，目标程序需能正常接收Typeless插入；每种应用仍需真机测试 |
| 任意语音识别即插即用 | 尚未实现；现有实现只接Typeless |
| 开发者替换语音后端 | Controller已有sink_factory和dictation_factory代码级扩展点，server目前仍直接构造TypelessToggle，没有通用插件加载器 |
| 语音后端协议 | start(target)、stop(target)、poll(target)、cancel()及processing属性；sink端start/write/close；仅有当前Typeless实现及测试，不等于其他ASR已适配 |
| typeless.hotkey配置 | 当前实际Right Alt仍在desktop.py内固定；不能只改JSON就换键 |
| virtual_audio.device/host_api配置 | 当前设备解析器实际固定查找VB-CABLE的CABLE Input及WASAPI；这些字段未完整接入 |
| 电脑麦克风选择 | local_microphone.device_regex确实被使用；需要唯一匹配有效设备 |
| ESP-IDF安装路径 | build.ps1已支持现成IDF终端，或显式传入-IdfExport/-IdfToolsPath，不再依赖旁边的私人项目缓存 |

因此本次发布定位应为“实验版：固定板型、Windows、Typeless；开发者可修改扩展”，不能宣传“任意ASR、任意AI路径一键替换”。要达到后一目标还需实现并验证语音provider注册、按键/设备配置生效、程序启动路径、动态AI入口及迁移安装流程。

## 发布

公共包只能包含白名单源码、样例配置和通用文档。不能发布local.json、local_config.h、已配置固件、备份、原始日志、录音、截图、会话库。原来的firmware-local.zip是本机私有包，不得作为GitHub附件。

本轮会准备独立干净目录与ZIP，不对整份工作区执行git add。GitHub连接目前没有返回可访问仓库，也未指定目标仓库；尚未上传。代码按MIT准备，中文字库保留SIL OFL，外部依赖通过ESP-IDF组件管理器按锁文件获取并遵循各自许可证。
