# 协议 V1

TCP，默认端口 8765；UTF-8 NDJSON，一行一个 JSON，最多 8192 字节，不含换行。服务器一次只服务一个设备。超时断开后清空会话，不能恢复旧录音。

连接后服务端返回 `{"v":1,"challenge":"64位随机十六进制"}`。客户端以 token 的 UTF-8 字节为密钥，对 challenge 的 UTF-8 字节做 HMAC-SHA256，返回 `{"v":1,"op":"hello","proof":"小写hex"}`。token 是本机生成的 64 字符秘密。随机挑战防重放登录；后续报文没有加密或独立 MAC，只供受信 WPA2 局域网测试，不开放公网。

每条请求含 `v:1`，可含 `id`，响应回显 id。固件连续发送音频并独立读取回复，控制请求按id关联；空闲时 500ms ping，服务端约 100ms 检查焦点。实际 UIA 延时可能增加检测时间，这不是实时安全保证。

| op | 字段 | 行为 |
|---|---|---|
| select | target: codex/chatgpt/grokbot; 可选 hwnd | 停止旧录音，查找并验证已有输入框 |
| start | 无 | 只在 ready 状态建立随机 record_id |
| audio | record_id, seq: 从0递增, pcm: base64 | 接收不超过3840字节、4字节对齐的PCM |
| stop | record_id | 再校验焦点，关闭WAV和元数据；自动听写时进入processing，其他模式进入idle |
| cancel/back | 无 | 保留取消记录，停止录音 |
| shortcut | key: escape/tab | 仅在非录音且焦点校验成功后发送白名单导航键 |
| ping | 无 | 返回状态 |

响应字段：state、error、target、window、session、record_id、saved、mode。session 未取到可靠证据时恒为 unknown，不从窗口泛化标题猜测。错误包括 NOT_READY、FOCUS_LOST、AMBIGUOUS_WINDOW、AMBIGUOUS_INPUT、INPUT_NOT_FOUND、UIA_UNAVAILABLE、AUDIO_SEQUENCE、STALE_RECORDING、BAD_PCM、AUDIO_TIMEOUT、MAX_DURATION 等。

录音最大300秒；无音频超过2秒停止；无有效消息超过3秒断开；Wi-Fi故障或TCP断线后固件每2秒尝试重连，必须重新选目标。休眠恢复通过单调时间超时作保守停止，尚未经历真实系统休眠验收。

音频修订：新增abort操作，错误白名单MIC_BUFFER_OVERFLOW、MIC_READ_FAILED、MIC_SAMPLE_GAP；未知错误折叠为DEVICE_AUDIO_ERROR。设备持续排空I2S，录音使用分代采样序号，缓冲溢出停止而不静默丢帧。完成时元数据记录audio_bytes、audio_seconds、wall_seconds、coverage_ratio；空录音或持续至少1秒但音频时长不足墙钟时长80%时，以incomplete/failed结束，错误EMPTY_RECORDING或AUDIO_DURATION_MISMATCH。

长录音修订：PCM不再逐包等待ACK；设备在同一TCP流上连续发送并非阻塞读取回复。所有请求带递增id，控制命令等待对应id，旧音频ACK不能冒充停止/选窗口回复。停止前发送完已采集队列，由TCP顺序保证全部先到的音频落盘后才关闭WAV。独立采集队列16帧（每帧20ms）；持续吞吐不足仍明确报错，不以大缓存掩盖丢音。

## 自动听写状态

本机启用`typeless_draft`模式。start仅在ready状态接受，虚拟音频建立后点按Right Alt开始。stop先排空音频再点按Right Alt结束，进入processing，保持焦点检查并等待输入摘要变化；成功后idle，45秒未变化则TRANSCRIPT_TIMEOUT。取消、失焦或断线使用Esc停止已启动的听写。程序不注入Enter。输入变化只作为出字信号，不代表语义校验。

队列内迟到的audio/stop保留本次首个终止错误，避免用STALE_RECORDING覆盖真实原因。只有当前processing录音可追加post_record_error，后续独立选窗口失败不修改上一条成功录音。

## V0.2 全局模式

新增`set_mode {mode:global|ai}`，全局为新固件默认主页；全局start抓取当前焦点而不定位/切窗，状态新增input_mode和warning。焦点变化取消并返回FOCUS_CHANGED_RECORDING_CANCELLED。录音及processing期间不接受切换模式/目标。AI会话为unknown时在严格配置下返回SESSION_UNVERIFIED。

新增`enter {action_id:每次物理点击唯一字符串}`，仅全局模式、非录音/processing时可用。服务端先记入去重集合再调用键盘；同action_id不重试，包括结果不确定时。每个助手实例最多4096个action_id，达到后明确拒绝；重启助手才清空，固件跨启动使用随机nonce加序号。默认普通Enter，可配置ctrl+enter；不推断应用是否发送消息。新增enter_actions与enter_injected计数，后者只表示SendInput调用返回成功，不代表应用消费结果。

空闲本地麦克风桥接可选开启。状态新增local_microphone、local_microphone_error、audio_source。路由不中断正常小屏采样协议；local为routing不等于真实Typeless转写已通过。

## V0.2 单点录音修订

小屏Global/AI均改为一次点击发起start、再次点击排空音频并发stop。触摸松开或滑出不停止录音；开始等待和结束排空期间不接受重复切换，250ms内重复点击忽略。断线、失焦、取消、音频异常和最大时长仍终止并清除录音请求，重连不自动恢复。AI模式在既有目标仍验证通过时可从idle再次开始，不重新定位或抢焦点。音频包、序号与时长完整性检查保持不变。
